# 產品需求文件 (PRD) — AI 面試作答平台 (Candidate Portal)

## 1. 文件資訊

- **產品名稱**：TechInterview Pro - Candidate Portal (AI 輔助面試作答系統)
- **文件版本**：v1.0
- **撰寫日期**：2026-08-04
- **文件狀態**：Draft / Reviewing
- **主要對象**：前端工程師、後端工程師、UI/UX 設計師、產品經理

## 2. 產品概述與目標

### 2.1 產品簡介

TechInterview Pro 是一款專為技術面試設計的應試者端平台 (Candidate Portal)。系統整合了專業的程式碼/架構解答編輯器，以及鑲嵌於右側的 Gemini AI Co-Pilot 面試助手。平台旨在評估求職者的程式撰寫能力、演算法邏輯、系統設計思維與 AI 工具協同解決問題的能力。

### 2.2 核心價值與目的

1. **真實情境模擬**：提供符合現代開發者習慣的輕量級、高度專注作答環境（Clean & Light Mode）。
2. **蘇格拉底式 AI 引導**：右側 AI 助手不直接提供現成程式碼解答，而是透過概念啟發、複雜度分析與邊界條件提問，評估面試者思考深度。
3. **高效率跨模組聯動**：題目、編輯器與 AI 側欄之間無縫互相傳遞 Context，降低應試者的操作切換成本。

## 3. 目標用戶與使用場景

- **目標用戶**：軟體工程師 / 全端工程師 / 系統架構師應試者（例如：Senior Full-Stack Engineer）。
- **主要場景**：
  - 應試者在規定時間內完成 2-3 道 Coding 或 System Design 題目。
  - 當遇到邊界條件或觀念卡關時，主動詢問 AI 取得方向提示（而非抄襲）。
  - 完成程式碼後，透過 AI Side Panel 進行 Code Review 並進行單元測試與最終提交。

## 5. 詳細功能規格

### F1. 頂部導覽列 (Top Header)

| 功能項目   | 規格與邏輯說明                                                                             |
| ---------- | ------------------------------------------------------------------------------------------ |
| 品牌標識   | 顯示系統 Logo 與名稱（TechInterview Pro）。                                                |
| 面試脈絡   | 顯示當前面試職稱（如：資深全端工程師模擬面試）。                                           |
| 倒數計時器 | 顯示剩餘時間（如 44:58）。時間小於 5 分鐘時變更樣式警示；降至 0 時自動鎖定作答並強制提交。 |
| 面試者資訊 | 僅精簡顯示面試者姓名（如：Alex Chen）。                                                    |
| 全螢幕模式 | 點擊切換進入/退出全螢幕。監聽 `fullscreenchange` 事件以自動更新按鈕狀態與 Icon。           |
| 提交全卷   | 點擊後彈出 Confirm 對話框，確認後提交並顯示 Toast 提示。                                   |

### F2. 題目區 (Question Panel — 左上)

| 功能項目         | 規格與邏輯說明                                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------------- |
| 題目頁籤         | 支援多題切換（如 Q1 API 限流器, Q2 LRU 快取, Q3 訊息佇列）。切換時需同步更換內容與編輯器預設模板。                      |
| 難度與配分       | 標註難度（Easy/Medium/Hard）與該題配分（如：40 分）。                                                                   |
| 題目內容         | 包含題目描述、功能規格、範例說明 (Input/Output)、時間/空間複雜度要求與評分重點。                                        |
| 詢問 AI 題目重點 | **跨組件聯動**：點擊後自動將預設 Prompt（如：「請簡要說明這道題目的核心評分要點」）傳送至右側 AI 對話框並觸發 AI 回覆。 |

### F3. 作答區 (Answer Workspace — 左下)

| 功能項目       | 規格與邏輯說明                                                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| 程式語言切換   | 下拉選單支援 JavaScript (Node.js)、TypeScript、Python、Go 等。切換語言時提示是否替換 Starter Code。                                     |
| 草稿自動儲存   | 監聽 Textarea input 事件，使用 Debounce (1000ms) 觸發儲存，並更新標題列圖示狀態（「儲存草稿中...」→「已自動儲存草稿」）。               |
| 程式碼格式化   | 點擊按鈕自動重新排版程式碼與縮排，並提示 Toast。                                                                                        |
| 編輯器與行號   | 支援行號對齊、語法高亮（視前端整合編輯器套件如 Monaco/CodeMirror 而定）、基本快捷鍵（Tab 鍵縮排等）。                                   |
| 執行單元測試   | 點擊發送程式碼進行測試，執行完畢後跳出 Toast 顯示通過數量（如：✅ 通過 5/5 個測試案例）。                                               |
| 傳送至 AI 檢查 | **跨組件聯動**：將目前 Textarea 中的程式碼打包附帶至 Context，自動觸發右側 AI 進行代碼 Review（檢驗 Corner Case、邊界條件與潛在 BUG）。 |

### F4. Gemini AI Side Panel (右側 AI 助手)

| 功能項目       | 規格與邏輯說明                                                                                                  |
| -------------- | --------------------------------------------------------------------------------------------------------------- |
| Context 綁定   | 頂部顯示 In-Context 狀態，代表 AI 自動捕捉當前所選題目與寫好的程式碼。切換題目時 AI Feed 自動加入切換系統通知。 |
| 引導模式切換   | 支援「輕度引導模式」與「深入討論模式」切換，控制 AI 回覆的詳細程度與揭露細節。                                  |
| AI 提示規範    | 頂部 Banner 規範：「AI 會協助解答觀念與優化，但不會直接給出完整解答」，遵守面試防作弊規則。                     |
| 快捷提問 Chips | 提供常用的快速提問按鈕（如：檢查 Corner Cases、複雜度分析、Redis 分散式擴充），點擊後直接發送。                 |
| 輸入區域       | 支援多行輸入、Ctrl + Enter 快捷傳送；夾帶當前作答區程式碼按鈕；語音輸入圖示（保留 UI 介面，預留 API 擴充）。    |

## 6. 非功能性需求

1. **視覺與體驗 (UX/UI)**
   - 採用柔和淺色系（Light Mode），適度留白（Padding/Margin），避免長文閱讀疲勞。
   - 視窗需具備響應式，左側題目與作答區、右側 AI 側欄比例維持約 6:4 或 7:5。
2. **效能要求 (Performance)**
   - 自動儲存草稿必須採取 Debounce 機制，降低伺服器請求頻率。
   - 程式碼編輯器輸入延遲需小於 50ms。
3. **安全性與公正性 (Fairness & Security)**
   - 全螢幕模式下若監聽至視窗失去焦點 (Blur Event / Page Visibility Change)，需發送提醒或紀錄異常切換行為。
   - AI 回應需設置 System Prompt 圍欄（Guardrails），嚴格限制其輸出完整可以直接 Copy-Paste 的最終答案。
